# Migration procedure

The 2026-11-04 Block/Port V1 request supersedes advanced search completion gates.
`BLOCK_PORT_V1_BASELINE.json` freezes the actual continuation37 state, not the
earlier paused35 description. Continuation37 measured M11 failure and then
stopped on a strategy admission rejection; no Provider node remained running.
Original M1-M10 evidence remains retained. The new migration does not restart P0
or regenerate those products.

New host conversion modules project frozen contracts, derive verification keys
and authenticate exact-boundary replacement certificates using original
ProvenanceGate receipts. Missing proof never means compatibility. Real-state
shadow comparison is in `BLOCK_PORT_SHADOW_RESULTS.json`; synthetic compatibility
tests do not substitute for the later real product replacement witness.

The library root is the current repository. Do not copy CGKN into it, or copy
library sources into CGKN. Use the isolated editable distribution recorded in
`governance/DEPENDENCY_IDENTITY.json`. Start CGKN checks and continuations with
that interpreter, with its Scripts directory first on PATH for subprocesses.

P0 captures Git identity, pre-existing dirty files and source hashes. Original
Promotion bytes are inventoried separately. The previous access failure receipt
remains preserved. P1 records module/symbol classifications and static callers;
dynamic caller removal is not inferred from absence in an AST inventory.

Migration receipts live in the host's `migration/veriarbor/` folder. Shadow
comparison uses real authenticated GoalAcceptance and synthetic counterexamples.
Compatibility imports preserve public host paths. Old generic implementations
are removed from production callsites and retained only as byte-exact rollback
snapshots. Never reset, clean or restore a whole dirty repository.

Rollback applies snapshots in reverse switch order only after verifying each
current file hash equals its receipt's after hash. If another edit has occurred,
stop and reconcile that file. Rollback never touches Promotion, Provider receipts,
Corpus, or accounting. Original failures and UNKNOWN records remain history.

Library, integration and product gates are separate. A passing unit test, shadow
comparison or certificate reconstruction does not establish M7 or final product
readiness. Product work resumes through the existing ProjectSession/Provider
route and canonical acceptance/delivery gates, with zero host business patches.
